## Responsibility boundaries

- **M10** remains the Core conformance foundation; its existing completion state is unchanged.
- **M11** remains compiler-service/editor-neutral infrastructure; M16.5 and M17–M21 may consume it but do not redefine its lifecycle/cache work.
- **M12** remains the distributed runtime vertical slice.
- **M13** remains the offline Calendar runtime vertical slice.
- **M14** remains media/cloud/realtime runtime plus bounded provider work.
- **M15** remains adapter ecosystem, migration/security/operational evidence, and 1.0 readiness.
- **M16** remains agent construction and verification, including the model-independent semantic task/evaluation machinery used by M16.5 before/after comparisons.
- **M16.5** is an additive language-surface normalization decision gate. It may choose retention, tooling/schema discoverability, or compatibility-sensitive normalization candidates, but it does not itself implement syntax or change support status.
- **M17–M20** add missing language/compiler/Canonical-IR implementation planning after applicable M16.5 hotspot dispositions are reviewed.
- **M21** generalizes the M10 evidence discipline to the full set of surfaces the project elects to support.

## Priority rationale

1. **M16.5** precedes broad M17–M20 expansion because the deterministic grammar review shows concentrated local construction irregularity; deciding what is intentionally stable versus a normalization/tooling candidate first avoids multiplying parser, semantic, IR, completion, fixture, and migration obligations around accidental forms.
2. **M17** is the first broad implementation milestone, because backend/frontend/profile surfaces depend on a coherent extended type system and independently versioned stdlib.
3. **M18** follows, because backend contracts are dependencies for distributed runtime, frontend data/mutations, and many compatibility facts.
4. **M19** follows once referenced operation/type contracts are compiler-authoritative.
5. **M20** closes architecture-heavy language contracts while keeping their runtime/provider execution in M12–M15.
6. **M21** comes last because exhaustive conformance is meaningful only after the intended supported language surface is implemented and applicable runtime/generator/editor evidence exists.
