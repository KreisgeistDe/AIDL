# M4 TypeScript domain generator

## Status

M4-02 implements the first generator slice for the M4 reference stack. It generates TypeScript domain declarations from canonical AIDL IR only. It does not add REST routes, persistence, transactions, idempotency, events, runtime wiring, package manifests, or build/run behavior.

## Generator boundary

`tools/generate_typescript_domain.py` exposes `generate_typescript_domain(ir)`. Its only semantic input is the canonical IR mapping produced by the M3 pipeline. The module does not import the AIDL parser, compiler project model, compiler diagnostics, or IntelliJ PSI and does not accept source paths.

The generator accepts canonical IR version `0.3.0`. Unsupported IR versions and unsupported type capabilities fail explicitly with `TypeScriptDomainGeneratorError`; semantics are never silently dropped.

## M4-02 declaration support

This slice generates the domain declaration kinds needed before API and persistence generation:

- `enum` as a TypeScript string-literal union;
- `alias` as a TypeScript type alias;
- `opaque` as its representation intersected with an AIDL-specific readonly brand;
- `value` as a readonly TypeScript interface;
- `entity` as a readonly TypeScript interface;
- `view` as a readonly TypeScript interface.

Other declaration kinds are not generated by M4-02. In particular, queries, mutations, APIs, errors, events, topics, consumers, workflows, sagas, and tasks remain for their roadmap-specific generator/runtime work.

The generator rejects duplicate domain declaration names that would collide in the single generated TypeScript module. It also rejects named or entity references whose target is outside the supported M4-02 domain declaration set.

## Type mapping

Canonical IR type references map deterministically as follows:

| AIDL IR type | TypeScript |
| --- | --- |
| `string`, `uuid`, `date`, `datetime`, `duration`, `revision`, `email`, `url` | `string` |
| `int`, `decimal` | `number` |
| `bool` | `boolean` |
| `bytes` | `Uint8Array` |
| named domain declaration | generated declaration symbol |
| owner-local `ref` | target entity symbol |
| list | `ReadonlyArray<T>` |
| set | `ReadonlySet<T>` |
| map | `ReadonlyMap<K, V>` |
| nullable | `T | null` |
| record | readonly structural object type |

IR field `required: false` becomes an optional TypeScript property. Nullability remains independent and is represented only when the canonical type reference is `nullable`.

M4-02 intentionally does not infer JSON serialization, database representation, validation libraries, runtime classes, or transport DTO behavior from these TypeScript types. Those concerns belong to later M4 items.

## Determinism

Generated declarations are sorted by canonical FQN and declaration ID. Property order and enum-value order are preserved from canonical IR because those arrays remain semantically ordered in the IR contract. The generator emits stable LF-terminated TypeScript text and has no filesystem, clock, environment, network, source-parser, or runtime-framework dependency.

Equivalent canonical IR therefore produces identical TypeScript domain output.

## Scope guardrails

M4-02 does not:

- add an `aidl generate` CLI command;
- create Fastify routes or REST schemas;
- generate PostgreSQL schema or migrations;
- implement transaction or optimistic-concurrency behavior;
- implement mutation idempotency;
- implement outbox/event integration;
- create package manifests, lockfiles, application scaffolding, or run scripts;
- establish the later generated-code ownership-marker mechanism.

The next M4 roadmap item may build API contracts/routes on top of these canonical-IR-derived domain declarations while preserving the M4-01 stack and IR-only generator boundary.

## Validation

`tools/test_generate_typescript_domain.py` covers supported domain declarations, canonical type mappings, deterministic ordering, explicit unsupported-capability failures, and TypeScript symbol collisions. The focused test is part of Python CI together with the M4 stack contract, M3 IR regressions, full Python suite, spec lint, and Petstore parser smoke.
