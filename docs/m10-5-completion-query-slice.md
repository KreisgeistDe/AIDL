# M10.5-04 bounded completion-query parity slice

This package adds only a Kotlin common-core completion query for the already migrated Gate-03 source-projection and name-resolution surface. Direct Core remains the permanent semantic authority. Python `tools.compiler_completion.complete_project_reference` and `CompilerSnapshot.complete` remain the migration reference/conformance oracle.

`ProjectCompletionQuery` owns no second resolver, workspace, index, cache, compiler service, adapter fallback, or public protocol. Saved text and one explicit in-memory replacement for an existing source identity are projected transiently, then candidate visibility is derived from `ProjectNameResolver`. The accepted context is conservative: completion is available only in reference-value positions inside the bounded projected declaration bodies. Module/import/declaration names, clause keys, other non-reference positions, lexical failures, unknown sources, and invalid offsets fail closed.

The parity matrix pins status, prefix, qualifier, candidate order, insert/display text, FQN, kind, origin, source identity, and source offset. It covers local and exact-import visibility, qualified names, empty-prefix completion immediately after `.`, ambiguous-name omission, prefix filtering, invalid parser positions, saved text, unsaved shifted text, repeated determinism, and reversed source enumeration. Normalization is limited to the fixture's source identity instead of temporary filesystem paths and Kotlin enum spelling; semantic candidate identity, ordering, offsets, prefixes, qualifiers, status, and ambiguity are not normalized away.

This slice does not migrate documentation, references, rename planning, fixes, inspect/dependencies/explain/impact, multi-root ownership, IDE/LSP protocol behavior, Native operational parity, or any M10.5-05+ / M11-04.1 / M11.5 architecture. It changes no language/schema/Core-authority/support/default-compiler contract. M10.5-04 remains incomplete after this package.
