# M10.3 Petstore disposition

This file records the Petstore-only M10.3-01 continuation against frozen M10.1 language-surface contract revision 4 and the integrated shared M10.3 authority in `spec/m10-3-shared-disposition.json`. It does not change parser/compiler/runtime/Canonical-IR semantics, Production Normalization admission, or the frozen contract.

## Result

The integrated shared foundation declares three equivalent canonical-source forms: app profile blocks, explicit entity `field` slots, and named query/mutation `parameters: [...]` HeaderArgs. This Petstore continuation migrates only forms that also survive the existing Petstore validation paths without semantic widening:

- `app.aidl`: all four app profiles use `profile Name { version N }`.
- `domain/adoptions.aidl`: `AdoptionRequest` members use explicit `field` slots.
- `domain/pets.aidl`: `Shelter` and `Pet` members use explicit `field` slots.

`m4-app/app.aidl` intentionally remains unchanged. Exact-head CI proved that the historical M4 production compiler path still requires legacy `profile ID version POSITIVE_MAJOR`; canonical profile blocks produced `AIDL-DIST414` before runtime generation. The runnable slice is therefore preserved as compatibility evidence rather than rewritten past its actual compiler support.

No other Petstore source meaning is widened. Positional query/mutation signatures remain parser-readable compatibility input in this slice; canonical named `parameters: [...]` remains the revision-4 target. Their excluded operation clauses remain fail-closed, so retaining those signatures does not contradict the target grammar or turn the operations into production evidence.

M10.3-01 remains open.

## Shared authority boundary

The integrated `spec/m10-3-shared-disposition.json` remains authoritative for shared mismatch classes:

- `app.profile-block`, `entity.field-slot`, and `operation.parameters-header-arg` are supported equivalent source forms at the shared parser/lint boundary.
- `app.links` uniquely remains `requires-versioned-admission`.
- auth/a11y/privacy, value/union/view, entity invariants, productive generic TypeRefs, operation auth/cache/consistency/idempotency/transaction, and the listed frozen-but-not-admitted product-story families remain `non-production-fail-closed`.

Equivalent parser/lint support does not imply every older production compiler path can consume a canonical spelling. The M4 CI failure is retained here as the concrete reason not to migrate that runnable source locally.

## Remaining Petstore work

A later, separately dispatched Petstore continuation may consider named operation HeaderArgs only while preserving every excluded body/execution clause as non-production evidence and proving exact parser/lint/runtime compatibility. Any work on `app.links`, additional semantic families, Production Normalization admission, Canonical IR meaning, or the frozen language contract requires separate central authority and is not an app-local migration.

The existing `m4-app/` remains useful runnable/generated compatibility evidence. A green toolchain run demonstrates that slice, not production admission for the broader Petstore language surface.
